01 · Story logic

先理解故事：两条控制链，不是同一个“风险分数”

ACT 1

付款入口：没有名单命中

Sahel Logistics 付款经过同步制裁筛查，没有潜在名单匹配，因此执行。

ACT 2

客户行为：出现异常组合

夜间监控回看完整行为窗口，把金额偏离、快速分散、新对手方和较高风险辖区组合成可解释案件。

ACT 3

人机协作：AI 整理，人做决定

AI 起草调查材料；Sarah 修改措辞、接受草稿并决定内部升级，所有动作进入审计轨迹。

ACT 4

付款入口：潜在名单匹配

Vladmir Petrov 的姓名高度相似，DOB 和国籍一致，因此付款先不执行，交由制裁复核。

核心结论

交易监控保护客户行为监控链路；制裁筛查保护付款入口。制裁信号不会进入 AML 案件优先级分数。

02 · Pre-flight

演示前准备

启动服务

在项目根目录运行：

docker compose up -d --build

打开演示控制台：http://localhost:8080/demo.html

开始前检查

  • 浏览器缩放建议保持 90%–100%，关闭无关标签页和通知。
  • 点击右上角 Reset demo，等待页面回到 Step 1 of 5 — Create Payment A。
  • 确认页面没有红色错误横幅，主按钮可点击。
  • 确认顶部时间轴显示 Yesterday 16:10–17:05、Yesterday 16:52、Today 02:00、Now。
  • 排练时完成一次全流程；正式演示前必须再次 Reset。
避免误操作

在 Step 1–3 期间不要从 Case Queue 点击全局 Run monitoring。只使用 Live Demo 页面中央的步骤按钮。

每次点击后等页面出现下一步按钮再继续，不要连续双击。

03 · Act 1

第一幕：昨天 16:52，付款通过

  1. 按键：点击 Create Payment A。

    应看到：Payment A 卡片出现，状态为 RELEASED，付款参考号为 PAY-000001，业务时间为 27 Jul, 16:52，Screening outcome 为 No potential sanctions match。

  2. 停留：指向 Status 和 Screening outcome，不要急着进入下一步。

ACME 提交 £26,000 给 Sahel Logistics。付款首先经过制裁筛查，没有发现潜在名单匹配，因此被释放执行。这里的结论不是“安全”，只是“没有名单命中”。
不要说

不要说“系统确认这笔付款安全”或“客户没有风险”。当前控制只回答：是否出现潜在制裁名单匹配。

04 · Act 2

第二幕：完整活动窗口与夜间监控

2A. 补全当天活动

  1. 按键：点击 Complete day activity。

    应看到：That day's activity 卡片显示：

    • 8 transactions over 55 minutes
    • £84,200.00 inbound
    • £77,464.00 outbound
    • 92.0% dispersal ratio
    • 4 first-time beneficiaries
现在回看昨天 16:10 到 17:05 的完整活动窗口。系统看到包括刚才那笔付款在内的八笔交易：£84,200 流入，随后 92% 快速流出，流向五个收款方，其中四个是新对手方。
时间线口径

不要说“付款之后又发生了七笔”。Payment A 位于 16:52；正确说法是“回看 16:10–17:05 的完整窗口，共八笔交易”。

2B. 运行夜间监控

  1. 按键：点击 Run overnight monitoring。

    应看到：New cases = 1；ACME 案件为 CASE-2026-0016；Priority 为 RED · score 83；Opened by 显示 28 Jul, 02:00。

  2. 按键：点击 Open the case Sarah is investigating。

到了夜间监控批次，系统不再孤立地看一笔付款，而是回看 ACME 的整体行为。系统发现了需要解释的异常活动，并把案件排到 Sarah 的队列前列。分数决定先看谁，不决定谁有罪。
05 · Act 3

第三幕：Sarah 调查、AI 草稿与内部升级

3A. 展开规则证据

  1. 按键：依次点击 R1、R2、R3、R4 四条规则标题展开证据。

    应看到：四条规则分数相加等于案件总分 83。

规则应看到的关键证据分数
R1 Amount deviation24h 流入 £84,200；90 天日流入中位数约 £9,535.86；比值 8.83×30
R2 Rapid dispersal流出 £77,464；分散比例 0.92×；5 个对手方；约 0.9h27
R3 New counterparties4 个新对手方；证据中包含 PAY-00000116
R4 Higher-risk jurisdiction流向 NG 的 £26,000；1 笔；证据为 PAY-00000110

3B. 查看交易时间线

  1. 操作：向下滚动到 Transaction timeline。

    应看到：16:10–17:05 共八笔交易；PAY-000001 在 16:52 被高亮并标记 focus，状态仍为 RELEASED。

每一分都可以回到具体规则和具体交易。这里显示的是需要调查的行为模式，不是对洗钱行为的认定。

3C. 生成并修订 AI 草稿

  1. 按键：点击 Generate draft。

    应看到：结构化草稿、Confirmed observations、Unexplained questions、Suggested next checks，以及可跳转的证据标签。使用容器启动时通常显示 model=template，这是正常的离线 fallback。

  2. 按键：在 NARRATIVE 右侧点击 Edit。

    删除或替换过度确定的句子 This may constitute layering.。建议把整段替换为：

    ACME Trading Ltd (CUS-000001) shows unusual payment activity in the review window with a priority score of 83 (RED). Inbound funds were followed by rapid outbound transfers across multiple counterparties. The observed pattern requires further investigation and a documented commercial explanation. Investigators should corroborate commercial purpose before any escalation decision.

  3. 按键：点击 Done，再点击 Accept。

    应看到：Edited and accepted by sarah.chen，Accept 按钮变为不可用，Audit trail 新增 AI_DRAFT_EDITED_AND_ACCEPTED。

AI 帮 Sarah 整理证据，但不替她做判断。Sarah 可以修改草稿，最终决定、理由和审计轨迹都由她负责。

3D. 内部升级

  1. 按键：在 Decision 中选择 Escalated – Internal。

  2. 输入理由：

    Unusual rapid dispersal across five counterparties, including four new counterparties and one higher-risk-jurisdiction payment, requires internal escalation and CRR review.

  3. 按键：点击 Submit disposition。

    应看到：页面重新加载后：

    • Case Status = ESCALATED_INTERNAL
    • CRR review = Required
    • Customer Monitoring = PENDING_REVIEW
    • Audit trail 包含 CASE_ESCALATED、CUSTOMER_MONITORING_FLAGGED、CRR_REVIEW_CREATED
教学重点

升级只创建 CRR review 并设置临时监控状态；它不会自动修改客户 CRR。正式风险评级仍需要授权复核人完成。

06 · Act 4

第四幕：制裁付款作为最终对照

4A. 提交 Payment B

  1. 返回：按浏览器 Back 回到 Live Demo；如没有回到 Step 4，直接打开 demo.html。

  2. 按键：点击 Submit Payment B。

    应看到：Payment B 卡片显示：

    • Payment reference = PAY-000002
    • Status = HELD — not executed
    • Name similarity = 0.972
    • Date of birth = EXACT
    • Nationality = EXACT
现在换一个收款人 Vladmir Petrov。系统发现姓名与制裁名单高度相似，同时生日和国籍一致，因此付款被暂挂；它还没有执行，executed_at 仍为空。
相似度口径

0.972 是字符串相似度，不是“97.2% 概率为同一个人”。身份判断仍由复核人员结合属性证据完成。

4B. 制裁复核并确认 Target match

  1. 按键：点击顶部 Sanctions Review。

    应看到：列表中唯一一条 Vladmir Petrov，Similarity 0.972，Status 为 Potential match。

  2. 按键：点击该行 Review。

    应看到：输入姓名 Vladmir Petrov 与名单姓名 Vladimir Petrov；DOB 1971-03-02 EXACT；nationality RU EXACT；Listed measures 包含 asset_freeze。

  3. 按键：Outcome 选择 Target match。

  4. 输入理由：

    Name is a high-similarity match and both date of birth and nationality match the listed individual exactly.

  5. 按键：点击 Resolve。

    应看到：详情收起，列表显示 No open potential matches。付款保持不执行，后台状态更新为 RESTRICTED_TARGET_MATCH。

前一条路径发现的是行为异常，所以系统交给调查员一份可解释的案件；这一条路径发现的是潜在制裁名单匹配，所以付款先不执行。一个保护支付入口，一个监控客户行为。

08 · Recovery

现场故障恢复

现象处理
页面不是 Step 1点击 Reset demo，等待重新播种完成。
按钮显示 Working…等待下一步按钮出现，不要刷新或双击。
页面提示状态冲突点击页面中的 Refresh state；仍不一致则 Reset demo。
AI 显示 model=template正常。离线 fallback 是确定性演示路径，不影响 AI 编辑和审计。
Accept 不可点击先 Generate draft；编辑后点 Done，再点 Accept。
Disposition 提交失败检查 Rationale 是否为空。
Sanctions Resolve 失败检查 Resolution rationale 是否为空。
Resolve 后列表为空正常；已解决的 hit 不再出现在 Potential match 队列。
无法访问 localhost:8080运行 docker compose ps；必要时重新运行 docker compose up -d --build。
最后手段

任何业务状态无法判断时，直接 Reset demo，从 Step 1 重新开始。Reset 会重建全部演示数据，因此不要在正式演示过程中误点。

09 · Quick run

一页速查：完整按键顺序

  1. Reset demo → 确认 Step 1。

  2. Create Payment A → RELEASED / 16:52 / No potential match。

  3. Complete day activity → 8 / 55min / £84,200 / 92% / 4 new。

  4. Run overnight monitoring → 1 new case / RED 83 / 02:00。

  5. Open the case Sarah is investigating。

  6. 展开 R1–R4 → 查看八笔交易时间线。

  7. Generate draft → Edit → 修改措辞 → Done → Accept。

  8. Decision 选择 Escalated – Internal → 填理由 → Submit disposition。

  9. 返回 demo.html → Submit Payment B → HELD / 0.972 / DOB EXACT / Nationality EXACT。

  10. Sanctions Review → Review → Target match → 填理由 → Resolve。

最终检查

组员能够解释清楚以下三句话，就算真正理解了演示：

  1. RELEASED 只表示没有潜在名单匹配，不表示没有其他风险。
  2. RED 83 是案件优先级，不是有罪概率。
  3. AI 帮助整理证据，最终判断和审计责任属于 Sarah。
